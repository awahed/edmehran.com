My engineering approach

Building software with AI, without losing engineering discipline.

AI-native. Spec-driven. Human-led.

AI is changing how we develop software, but generating code is only one part of building reliable systems.

I've developed a practical engineering workflow that combines Spec-Driven Development, AI-assisted implementation, multi-agent orchestration, automated testing, and code review by a separate AI agent.

Development starts with clear requirements, architectural decisions, and measurable acceptance criteria. Testing and code review are iterative parts of implementation, while human oversight and final approval remain central.

At Vivento Lab, we apply these principles across our software projects, adapting the workflow to the requirements and complexity of each project.

  1. 01 Specification Approved requirements, architecture, and acceptance criteria.
  2. 02 Task management Versioned specifications, tasks, and review history. Backlog.md
  3. 03 Implementation AI-assisted development with developer checks. e.g. Claude Code
  4. 04 Verification Automated tests and browser verification. e.g. Playwright
  5. 05 Code review A separate AI agent checks requirements, quality, security, and potential regressions. e.g. Codex
  6. 06 Human approval Final human approval, separate from deployment.
Failed checks return work to implementation.

Implementation, testing, and code review are iterative. Failed checks return work to implementation. Tools change, but the principles remain.

AI accelerates execution. Engineering discipline supports quality. Human judgment remains in control.
